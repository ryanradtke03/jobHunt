# Rewording Guide

Guidance for Step 3 of `SKILL.md` — the *light rewording* of an already-selected, already-true bullet, not writing a new one from scratch. The bullet's content, scope, and every number are fixed by the pool; the only thing in play here is phrasing.

## Weak openers — never introduce these when rewording

If a bullet's original text already starts strong, don't weaken it. If you're adjusting the opening to better match the JD's language, don't land on one of these:

| Weak | Why | Use instead |
|---|---|---|
| "Responsible for" | Passive, says nothing about the outcome | The actual strong verb already in or implied by the bullet: Built, Led, Designed, Reduced, Automated... |
| "Helped" / "Assisted" | Diminishes ownership | Only use if the original bullet is genuinely describing a supporting role — don't inflate it, but don't undersell it either |
| "Worked on" | Vague | Developed, Built, Implemented |
| "Utilized" | Pretentious for "used" | Used, or name the specific action taken |
| "Participated in" | No ownership signal | Contributed to, Co-led |

Never swap in a *stronger* verb than what the original bullet's facts support — that crosses from rewording into fabrication, which `SKILL.md` Step 3/4 already forbids. This table is about not making a bullet *weaker* while adjusting it, not about upgrading it.

## Mechanical formatting rules

- No trailing period — bullets aren't sentences.
- No personal pronouns (I, my, we, our).
- Digits stay digits ("8", not "eight"; "30%", not "thirty percent") — this is purely a formatting rule, not license to change *which* digits appear; the pool's original numbers are still the only ones allowed (see `SKILL.md` Step 4).
- Avoid excessive adjectives/adverbs (excellent, innovative, successfully, independently) — they read as filler, not signal.
- Keep it to roughly one line, two at most; if a reworded version runs noticeably longer than the original, you're probably adding words rather than adjusting them.

## Matching the JD's language (the actual point of rewording)

This is the real reason Step 3 allows rewording at all — not to make bullets sound better in the abstract, but to use the JD's own terminology where the bullet's underlying fact already supports it:

1. Read the JD and note its specific terms — technology names, methodologies, the exact phrase it uses for something the pool bullet also describes (e.g. the JD says "CI/CD pipeline", the bullet says "automated deployment via GitHub Actions" — if that's the same fact, using the JD's phrase is fair rewording, not fabrication, because the bullet's original text already contains "GitHub Actions").
2. Only do this where the underlying bullet fact genuinely matches — don't stretch a bullet to cover a JD requirement it doesn't actually satisfy just because a keyword would look good.
3. Prefer reordering/selecting (which bullets, in which order) over rewriting when in doubt — moving the most relevant already-true bullets earlier does more for a resume's read than aggressive rewording of any single bullet.
4. If the JD asks for something the pool genuinely has no bullet for, leave it uncovered. Do not manufacture a bullet or stretch an unrelated one to imply it — the user will be asked about everything on their resume in an interview.
